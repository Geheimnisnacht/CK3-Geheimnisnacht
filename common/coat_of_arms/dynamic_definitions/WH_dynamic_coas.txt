
# Follows vanilla's own dynamic_coa pattern (see game/common/coat_of_arms/dynamic_definitions/00_dynamic_coas.txt, e.g. e_north_sea):
# "holder = title:X.holder" means "this title's holder is the same character as title X's holder" - no separate named trigger needed.
#
# Tier note: an EARLIER draft of this fix (and the original coa_bretonnia_*_trigger names) pointed at duchy-tier (d_X) titles.
# That was corrected after finding events/coat_of_arms/coa_events.txt: a never-activated but fully-written companion mechanism
# (commit 05766a8c "[fix] resolved all Bretonnia errors.", written already-commented, so never proven working - restored once
# by mistake in b2a45006 while still commented) that drives this exact same e_bretonnia CoA switch off KINGDOM-tier titles
# (has_title = title:k_quenelles etc.), not duchies. That's also the structurally correct tier here: Bretonnia's emperor is
# elected from among the 14 kingdom-tier rulers (k_bastonne, k_couronne, ...), each of which de jure contains a same-named
# duchy that is normally held by a VASSAL duke, not the emperor personally - so checking d_X.holder would usually be false
# even when the emperor genuinely IS "of House X". Checking k_X.holder matches how the title tree is actually structured.
# All 15 e_bretonnia_* coat_of_arms below are confirmed to exist in common/coat_of_arms/coat_of_arms/wh_dynamic_coa.txt, and
# all 14 k_X kingdom titles below are confirmed to exist in common/landed_titles/wh_landed_titles_bretonnia.txt.
# Neither d_herrimault nor k_herrimault exists anywhere in the mod (checked both tiers), so e_bretonnia_herrimault - which
# does exist as a CoA asset - has no title to hook a holder-equality check to; left commented rather than guessed.
